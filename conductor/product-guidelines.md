# Product Guidelines: OmniSync

## Tone and Voice
-   **Functional and Direct:** Primary communications should be concise, unambiguous, and focused on the task at hand. Avoid fluff.
-   **Power-User Oriented:** Technical terminology is acceptable and encouraged where it adds precision. Assume the user understands system concepts (e.g., "Service," "Process," "SignalR").

## Visual Identity & UI Principles
-   **Dark Mode First:** The default aesthetic should be dark mode to suit developer environments and reduce eye strain.
-   **Functional Utility with Polish:**
    -   Prioritize information density and quick access to controls.
    -   Use modern design elements (Material Design principles) to ensure the interface is clean, consistent, and visually appealing, without sacrificing utility.
    -   Subtle animations can be used to provide feedback (e.g., connection status changes), but should not delay interaction.
